# План розробки

## Фаза 0 — Фундамент (перш ніж будь-яка "розумна" логіка)
Мета: скелет, що вміє надійно зберігати дані. Без цього аналіз будувати нема
на чому.

- [ ] Обрати стек (мова, БД, оркестрація) — зафіксувати в CLAUDE.md
- [ ] Базова схема БД: сирі дані, метадані джерел, лог релізів
- [ ] Один-єдиний адаптер джерела даних (напр. один макро-показник з одного
      безкоштовного API) — наскрізно, від збору до збереження
- [ ] Налаштування Telegram
- [ ] Мінімальний тест: дані зібрались → лежать у БД → їх можна дістати та формування і відправка повідомлення останіх свіжих даних.

**Критерій завершення фази:** можна руками запустити збір одного показника
і побачити результат у БД. Нічого розумного ще не робимо.

## Фаза 1 — Збір даних (ширина, не глибина)
- [ ] Макро-дані: 3-5 ключових показників (інфляція, ставки, безробіття, ввп —
      залежно від ринків, які цікавлять)
- [ ] Дані компаній: звіти (earnings), базові фінансові метрики
- [ ] Новини: підключення джерела + фільтрація за релевантністю
- [ ] Календар релізів (коли виходять наступні дані) — це критично для
      Фази 3 (моніторинг)
- [ ] Нормалізація: усі джерела приводяться до єдиного внутрішнього формату

**Критерій завершення фази:** дані з кількох різних джерел стабільно
збираються за розкладом без ручного втручання.

## Фаза 2 — Аналіз і прогнози
- [ ] Формування "ринкових очікувань" для показника (звідки їх брати —
      окреме дослідження: консенсус-прогнози, або власна модель)
- [ ] Порівняння факту з очікуванням при виході нових даних
- [ ] Базовий механізм прогнозування (почати з простого — наприклад,
      трендові моделі — перш ніж ускладнювати)
- [ ] LLM-аналіз новин/звітів → структурований висновок (не вільний текст)

**Критерій завершення фази:** для одного показника агент може сказати
"вийшло X, очікувалось Y, це означає Z" одразу після релізу.

## Фаза 3 — Моніторинг і реакція
- [ ] Трекінг календаря релізів, тригер на "дані щойно вийшли"
- [ ] Автоматичне оновлення прогнозів після кожного релізу
- [ ] Сповіщення про суттєві відхилення від очікувань

## Фаза 4 — Звітність і списки активів
- [ ] Генерація короткого регулярного звіту (щоденний/щотижневий)
- [ ] Формування списку "цікавих активів" на основі накопиченого аналізу
- [ ] Формат видачі (email/dashboard/файл — вирішити окремо)

## Поза MVP (навмисно відкладено)
- Бектестинг стратегій
- Портфельна оптимізація
- Мультикористувацький режим / авторизація
- Реальні угоди/виконання ордерів (агент тільки аналізує, не торгує)
