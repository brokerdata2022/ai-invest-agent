## Фаза 0 — Фундамент (перш ніж будь-яка "розумна" логіка)
Мета: скелет, що вміє надійно зберігати дані. Без цього аналіз будувати нема
на чому.

- [x] Обрати стек (мова, БД, оркестрація) — зафіксувати в CLAUDE.md
- [x] Базова схема БД: сирі дані, метадані джерел, лог релізів
      (db/schema.sql: raw_observations, sources, release_log)
- [x] Один-єдиний адаптер джерела даних (FRED, CPI/fed_funds_rate/
      unemployment_rate) — наскрізно, від збору (fetch) до нормалізації
      (normalize) і збереження (common/db.py)
- [x] Налаштування Telegram (reporting/telegram_notify.py, потребує
      TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID в .env)
- [x] Мінімальний тест: дані зібрались → лежать у БД → їх можна дістати
      та сформувати і відправити повідомлення останніх свіжих даних.
      Живий наскрізний прогін (run_collect.py → реальна TimescaleDB →
      telegram_notify.py) виконано і підтверджено локально 2026-08-29.

**Критерій завершення фази:** можна руками запустити збір одного показника
і побачити результат у БД. Нічого розумного ще не робимо.

## Фаза 1 — Збір даних (ширина, не глибина)
- [x] Макро-дані: 3-5 ключових показників (інфляція, ставки, безробіття, ввп —

      (companies/sec_edgar_adapter.py — revenue/EPS/shares/assets/
      liabilities) + ціни/обсяг через Twelve Data (quotes/twelvedata_adapter.py)
- [x] Новини: news/ повністю реалізовано (GDELT + офіційний RSS,
      3 потоки, класифікація DeepSeek, агрегація) — докладніше
      docs/status.md
- [x] Крипта (BTC/ETH/SOL, docs/watchlist.md): Binance (ціна/обсяг) +

- [x] Календар релізів (коли виходять наступні дані) — `monitoring/`,
      15 показників (US через FRED + EUR/JPY через ECB/BOJ/e-Stat,
      2026-09-27 — watchlist торгує EUR/USD, USD/JPY), двофазно:
      `refresh_calendar.py` (тижнево, дата+час/impact/forecast) —
      живо підтверджено; `check_releases.py` (часто, активно
      тригерить збір) — код готовий, live-прогін чекає на 1 жовтня
      (docs/decisions.md, 2026-09-27)
- [x] Нормалізація: усі джерела приводяться до єдиного внутрішнього формату
      (NormalizedRecord, common/adapter.py) — застосовано послідовно у
      всіх 6 адаптерах (fred/ecb/boj/estat/sec_edgar/twelvedata)

**Критерій завершення фази:** дані з кількох різних джерел стабільно
збираються за розкладом без ручного втручання — виконано
(`orchestration/`, 2026-09-27, docs/decisions.md). Форекс/товари поза
watchlist-парами — закрито як окрема задача (рішення користувача,
2026-09-26): розширення переліку користувач вносить сам через файл
вибраних активів.

**Паралельний трек (випередив цю фазу):** скринінг акцій S&P 500
(analysis/screening/ — Tier A/B/C + composite score, критерії —
docs/screening-criteria.md) реалізований і живо підтверджений
повністю. Це інший вид аналізу (детермінований відбір/ранжування

чи LLM-прогноз) — концептуально ближче до Фази 4 ("список цікавих
активів"), але не потребував завершення Фази 2/3, тому зроблений уже
зараз. Деталі — docs/status.md.
