# Критерії скринінгу акцій

Пороги й формула нижче узгоджені з користувачем 2026-09-20 — це вже не
чернетка, а робоча версія (може уточнюватись після першого реального
прогону на живих даних, коли буде видно фактичний розподіл значень).

## Мета

Відібрати ~10 акцій-кандидатів для моніторингу/торгів із звуженого
universe топових ліквідних компаній — а не просто топ-N за
капіталізацією і не довільний список "цікавих" тикерів. Список — вхід
для `companies/` (SEC EDGAR): збираємо фундаментальні дані **тільки**
по вже відфільтрованих тикерах, а не по всьому ринку.

Порядок роботи: `quotes/twelvedata_adapter.py` → прогін скринера на
universe → `companies/` тільки для відібраних тикерів.

## Джерела даних

| Дані | Джерело | Статус |
|---|---|---|
| Universe (базовий пул) | S&P 500 constituents, `github.com/datasets/s-and-p-500-companies` | джерело обрано — свідомо звужений пул, не весь ринок (див. нижче) |
| Ціна, обсяг торгів, історія | Twelve Data | джерело обрано (виняток з "official first" — безкоштовного офіційного джерела котирувань окремих акцій не існує; реєстрація email+пароль, без капчі — на відміну від відкинутого Alpaca/Stooq, docs/decisions.md) |
| Виручка, чистий прибуток, EPS, к-сть акцій в обігу, борг | SEC EDGAR (companyfacts/companyconcept) | ще не побудовано — наступний крок після цього документа |
| Ринкова капіталізація | розрахунок: ціна (Twelve Data) × shares outstanding (EDGAR) | — |
| Позачергові кандидати з новин | `news/` (GDELT) | не побудовано, у плані поза макро (див. PLAN.md) |

## Воронка відбору

```
Universe: S&P 500 (~500 тикерів, замість ~8000+ у повному SEC-лістингу)
   → Tier A: ліквідність (Twelve Data — ціна, обсяг)
   → Tier B: фундаментальна якість (SEC EDGAR)
   → Tier C: valuation (Twelve Data ціна + EDGAR EPS/Revenue)
   → composite score → топ 10
```

Паралельно — окремий, позаплановий шлях додавання через новини (розділ
нижче).

### Universe — свідомо звужений

Базовий пул — constituenti **S&P 500**
(`https://raw.githubusercontent.com/datasets/s-and-p-500-companies/main/data/constituents.csv`),
а не весь `company_tickers_exchange.json` SEC (кілька тисяч тикерів).
Причини: (1) не сканувати "весь мотлох" — S&P 500 вже
попередньо якісний, ліквідний, великокапітальний пул; (2) суттєво
менше запитів на Twelve Data за прогін (~500 замість кількох тисяч).
Список S&P 500 оновлюється нечасто (кілька ребалансувань на рік) —
достатньо звіряти на кожному плановому прогоні (щокварталу, див.
нижче), окремий моніторинг змін індексу між прогонами не потрібен.

### Tier A — ліквідність і якість лістингу (Twelve Data)

| Критерій | Поріг |
|---|---|
| Біржа | NYSE або NASDAQ |
| Ціна акції | > $10 |
| Ринкова капіталізація | > $10 млрд (large-cap) |
| Середній обсяг торгів (3 міс) | > $10 млн/день (доларовий обсяг — коректно порівнює акції з різною ціною) |

### Tier B — фундаментальна якість (SEC EDGAR)

| Критерій | Поріг | us-gaap concept |
|---|---|---|
| Прибутковість | `NetIncomeLoss` > 0 останні 4 квартали поспіль | `NetIncomeLoss` |
| Зростання виручки | YoY > 10% | `Revenues` (або `RevenueFromContractWithCustomerExcludingAssessedTax` — не всі компанії використовують один і той самий тег, перевіряти по факту) |
| Зростання EPS | YoY > 15% | `EarningsPerShareDiluted` |
| Дисципліна щодо акціонерів | к-сть акцій в обігу не зросла > 3% YoY | `EntityCommonStockSharesOutstanding` (dei) |
| Борг | `Liabilities` / `Assets` < 0.6 | `Liabilities`, `Assets` |

### Tier C — valuation (Twelve Data ціна + EDGAR EPS/Revenue)

| Критерій | Поріг | Навіщо |
|---|---|---|
| P/E (ціна / EPS diluted TTM) | 10–35 | відсікти і value-trap (замало для growth-кандидата), і шалено переоцінене |
| P/S (капіталізація / виручка TTM) | < 8 | додатковий фільтр переоціненості |
| PEG (P/E ÷ EPS growth %) | < 2 | growth-at-reasonable-price — страхує від "росте на 15%, але P/E вже 60" |

### Ранжування (composite score)

Серед кандидатів, що пройшли всі hard-фільтри Tier A+B+C:

```
score = 0.35 × percentile(revenue_growth_yoy)
      + 0.30 × percentile(eps_growth_yoy)
      + 0.20 × percentile(-P/E)              # нижчий P/E → вищий ранг
      + 0.15 × percentile(avg_dollar_volume)  # ліквідність як tie-breaker
```

`percentile(x)` — процентильний ранг (0-100) значення `x` серед
кандидатів, що пройшли hard-фільтри в **поточному прогоні** (не серед
усього S&P 500) — уникає довільної нормалізації різних шкал. Топ-10 за
підсумковим `score`. Ваги (35/30/20/15) — стартова точка, зростання
важливіше за дешевизну для growth-кандидатів; підлягають калібруванню
після першого реального прогону.

### Позачергове додавання за новинами

Окремо від планового щоквартального прогону: акція, що спливає в
новинах (майбутнє джерело `news/`, GDELT — ще не побудовано), може
потрапити в список поза чергою — **але тільки після проходження Tier B**
(фундаментальна перевірка), новинний привід сам по собі підставою не є,
лише тригер для позачергової перевірки конкретного тикера:

```
Новина про тикер X → Tier B перевірка X (SEC EDGAR)
   → пройшов → додається до списку до наступного планового ребалансування
   → не пройшов → відкидається
```

`companies/` (SEC EDGAR) вже спроєктований під одиничний виклик по
довільному тикеру (тикер — параметр, не хардкод), тож додаткової
роботи для цього шляху не буде потрібно, коли з'явиться `news/`.

## Частота ребалансування

Синхронно зі звітністю: повний перезбір і переранжування списку після
кожного циклу 10-Q (щокварталу, коли компанії зі списку публікують нові
квартальні цифри).

## Де це реалізується

Сам скринінг — це `analysis/` (Фаза 2), не `data-ingestion/`: він
обчислює похідні величини (YoY %, P/E, score) і приймає рішення на
основі них, а `data-ingestion/` за принципом проєкту зберігає тільки
сирі значення. `data-ingestion/` дає для цього сирі дані (Twelve Data —
ціна/обсяг, SEC — universe і фундаментальні факти); сам скринер
з'явиться пізніше, коли дійдемо до `analysis/`.
